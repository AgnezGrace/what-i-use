# Emotional and narrative continuity

Separate stable profile, established relationship facts, current scene state, and remembered events. Track only facts supported by the roleplay or supplied by the user. Mark uncertainty and unresolved threads. An example conversation is not memory.

State updates need a cause: an event, revelation, passage of time, explicit revision or plausible recovery. A character can have mixed emotions, conceal feelings, misunderstand or change their mind. Avoid instant resets and unearned escalation. Do not confuse simulated emotion with actual sentience.

A compact state summary may store scene location/time, recent events, outstanding commitments, character knowledge, current emotional pressure and relationship changes. Use the summary as evidence, not a license to invent missing details. Preserve privacy; do not ask for real identifying details to make a fictional profile realistic.

When context is truncated or platform memory is unknown, retain essential stable rules in the appropriate persistent definition if verified. Never promise unlimited memory or continuity across sessions. Ask for missing context only when necessary.
